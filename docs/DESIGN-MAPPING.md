# 设计交付 → 生产实现 映射

源：`Downloads/wenjian`（OpenDesign handoff，`DESIGN-MANIFEST.json`）

## 屏幕映射

| 设计文件 | 生产路由 | 说明 |
|----------|----------|------|
| `index.html`（launcher-overview，实际是电脑控制台） | `/` | 保留五视图结构（概览/文件/共享/设备/设置）与抽屉、对话框、Toast |
| `web.html`（手机网页版） | `/w/<token>` | 免安装会话；有会话 cookie 时可上传/下载；本轮补了预览、搜索、文件夹筛选与「电脑发来」
| `mobile.html`（iPhone App） | `/app` | 实现为可安装 PWA，四标签页与底部 Sheet 与设计一致 |
| `android.html`（Android App） | `/app` | Android 与 iOS 共用同一 App 版；系统状态栏由真机提供，不绘制假设备外壳 |
| `pair.html`（配对页，设计稿未包含） | `/pair` | 6 位配对码入口，补齐扫码失败路径 |
| —（设计稿未包含） | `/s/<code>` | 共享链接落地页，承接控制台的「生成共享链接」 |

设计稿中的 `assets/tokens.css` 原样沿用；`desktop.css` 沿用并新增抽屉发送面板、空状态等少量样式；`phone.css` 整体沿用，另加 `app-shell.css` 负责真机全屏布局（去掉设计预览用的机身外壳、灵动岛、状态栏）。

## 有意偏离设计的地方

| 设计稿 | 实现 | 原因 |
|--------|------|------|
| 手机预览外壳（机身、刘海、Home 条、假状态栏） | 全屏 App + 桌面端居中窄栏 | handoff 明确要求去掉预览 chrome；“一台自适应 Web 体验”优先于三张固定截图 |
| App 内「已自动接收」 | 「点按保存 / 已收到」 | 浏览器无法在无用户手势时静默写入相册或下载目录，如实标注状态 |
| App 版 = 原生 App | App 版 = PWA | 本次不打包原生；PWA 可全屏、可接收局域网 SSE 推送、可添加到主屏幕 |
| 网页版底部「装个 App，电脑也能发给你」 | 保留，并链接 `/app` | 与实现能力一致 |
| 控制台的 iPhone / Android 预览入口 | 手机网页版 / App 版 / 配对入口 | 生产环境没有“预览”概念，改为真实入口 |
| 控制台 Hero（“你的电脑，就是网盘。”+ 三格统计条） | 删除，指标收进底部状态栏 | 落地页式大标语占掉首屏却零信息；桌面工具不需要说服用户 |
| 右栏「网页版 / 配对码」两张卡片 + 「隔壁同事，也能直接取」软文卡 | 合并成一块配对面板 + 一行说明 | 同一件事讲三遍，还把右栏撑出滚动条 |
| 「刚刚收到」与「最近文件」两个列表 | 合并为一个「最近文件」列表 | 数据源高度重叠，同屏出现两份几乎相同的文件行 |
| 每行尾部常驻「已保存」 | 只在传输中显示进度，完成后不写状态 | 五行「已保存」是纯噪音 |
| 页面内再写一遍大标题（`view-head`） | 顶栏只保留一处标题 | 原来「文件」在顶栏和正文各出现一次 |

## 桌面排版

第一版直接照搬手机稿的卡片堆叠：大圆角白卡、营销大标题、右栏三块软文、整页滚动。放在 1440×900 的原生窗口里像把 App 塞进桌面，因此重做了排版层。

| 部位 | 做法 |
|------|------|
| 骨架 | `208px 侧栏 / 52px 顶栏 / 主区滚动 / 28px 状态栏` 四段固定，只有主区滚动 |
| 侧栏 | 深色 rail 改浅色（`#f2f4f0`）+ 1px 分隔；导航 32px 行高，激活态浅绿底，不再用深色块压边 |
| 顶栏 | 左侧一页一个标题（副标题跟在同一行、竖线分隔），右侧搜索 + 配对；不重复正文标题 |
| 状态栏 | 服务地址、已接收数、占用空间、在线设备、存储路径常驻底部，替代原来的三格统计条 |
| 面板 | 圆角 16 → 9px，去掉投影，只留 1px 边框；标题 13px、说明 11.5px |
| 列表 | 文件改成 46px 表格式行（图标 / 名称+来源 / 大小 / 箭头），不再是一张张卡片 |
| 空态 | 居中：图标 + 一句主文案 + 一句指引，落在工作区中央，而不是左上角一行灰字 |
| 拖放区 | 从 220px 大方块压成 76px 横条（图标 / 文案 / 按钮三段），把纵向空间让给文件列表 |
| 高度 | 概览面板 `clamp(356px, 46vh, 512px)`，文件多了自然长高；文件页列表 `min-height 420px` 并撑满 |
| 设置页 | 两栏卡片改单栏分组，`max-width 700px` 居中，行间用分隔线而不是卡片 |
| 短窗口 | 骨架行 `minmax(0,1fr)`，侧栏与主区都带 `min-height: 0`，窗口压到 600px 高时状态栏与侧栏底部仍在可视区，只让主区滚动 |


## 预览、归档与 Skill（第二轮扩展）

设计稿只画了「文件列表」，没有规定点开文件之后发生什么，也没有目录、存储选择、对外能力的入口。这一轮补的是这四块，原则仍是：能复用设计 Token 就不新增视觉语言。

| 需求 | 做法 | 取舍原因 |
|------|------|----------|
| 多格式预览 | 浮层 `#preview`，白底、9px 圆角、顶部工具条（文件名 / 缩放 / 下载 / 用系统程序打开 / 关闭），按 `kind` 换渲染器 | 浮层不打断列表上下文，退出后滚动位置还在；另开页面会把「看一眼」变成一次导航 |
| 预览数据来源 | 服务端 `/api/files/:id/preview` 返回结构化 JSON；媒体走 `/api/files/:id/raw` 的 `inline` 流 | 浏览器不该为了看一眼 docx 先下载整个文件；Office 与 zip 在服务端解包 |
| 图片 | 白底容器 + `object-fit: contain` | 深色底会把透明 PNG 和演示图压暗，也和文档预览的白纸不一致 |
| 表格 | 前端自绘 `<table>`，首行当表头，300 行 × 30 列封顶 | 引入表格组件只为一个只读视图，不划算；封顶防止大 CSV 卡死渲染 |
| 老版 Office | 明确写「暂不支持内嵌预览」并给两个出口 | 假装能预览或静默失败都比直说更糟 |
| 文件夹 | 左栏 176px 树 + 面包屑；文件对象只存 `folderId` | 移动是瞬时操作、不跨盘失败、不用处理占用与权限；代价是磁盘上不分层（已在 README 已知边界写明） |
| 建夹 | 支持 `归档/2026-10` 路径写法，逐级补齐 | 一次输入就能建出层级，比「先建父再建子」少一半点击 |
| 删夹 | 只删夹，文件回上一级 | 删除目录连带删文件是最容易造成数据丢失的交互，不做 |
| 行内操作 | 悬停才出现 `.row-actions`（预览/移动/共享/删除） | 常驻四颗按钮会把 46px 的文件行塞满，扫读成本高于操作便利 |
| 移动 | 独立对话框 + 文件夹选择器，支持批量 | 拖拽排序在长列表里容易误触，且手机端没有拖拽 |
| 存储目录 | 设置里可手输、可浏览目录（`/api/fs/list`）、可勾选迁移 | 迁移复用同一套索引，搬完文件夹归属与标签都还在，用户不用重新整理 |
| Skill | 设置页一块面板：端点、令牌（可复制/轮换）、命令行示例、下载 zip、预览整理方案 | 把「机器可调用」的能力摊开给用户看，而不是藏在文档里；令牌可见才能自证安全边界 |
| 手机端 | 不做原生、不做 Flutter，直接强化 `/w`：预览弹层、搜索、文件夹胶囊、「电脑发来」卡片 | 一套 Web 三端复用，省掉签名与双端发版；用户要的「上传/下载/推送」网页都能做 |

移动端「电脑发来」用 `grid-template-columns: 38px minmax(0,1fr) auto`——首版只写了两列却塞了图标、文本、按钮三个子元素，按钮被挤到下一行，是这轮唯一一个纯排版 bug。

## 桌面承载方式（Tauri 壳）

设计交付包只给了界面，没有规定桌面端怎么承载。第一版是浏览器打开 `localhost`；现在桌面端是 Tauri 应用，**应用自己就是服务器**。

| 事项 | 做法 |
|------|------|
| 窗口 | 原生 WebView2 窗口，标题栏/最小化/最大化/缩放都交给系统，不绘制假 chrome |
| 服务启动 | Rust 先挑空闲端口（17800 起），再拉起内置后端，等 `/api/health` 真返回 200 才建窗口，避免白屏和"页面加载失败" |
| 后端形态 | `esbuild` 打成单 CJS，用 Node SEA 注入 node.exe 副本，产物 `landrop-server.exe` 约 83 MB，用户机器无需装 Node |
| 静态资源 | `public/` 作为 Tauri resource 随安装包分发，运行时从安装目录读取（已用"改名项目 public"的方式验证过不依赖源码目录） |
| 关闭窗口 | 隐藏到托盘，服务继续跑；真正退出在托盘右键菜单 |
| 拖拽上传 | 关掉 Tauri 的拖放接管（`disable_drag_drop_handler`），让 WebView2 走原生 HTML5 拖放，否则页面收不到 drop 事件 |
| 新窗口链接 | WebView 不处理 `target="_blank"`，改由 `/api/open-external` 交给系统默认浏览器；只放行本机与私有网段，`file://`、公网地址一律 403 |
| 单实例 | 第二个实例把已有窗口唤到前面后自行退出，不会起第二个服务 |
| 被强杀 | 后端通过 stdin 管道感知 App 消失并退出，不留占端口的孤儿进程（实测 4 秒内退出） |

## Token

来自 `assets/tokens.css`，未新增品牌色：

- 背景 `#f1f3ef`，表面 `#ffffff`，墨色 `#0f1512`，分割线 `#dce2db`（桌面端另加一档 `--ink-4` 作弱化文字）
- 主色 `#14523f`，悬停 `#0d3f30`，强调底 `#e0eee7`
- 高亮 `#c9f65a`（桌面端只用于在线点，`#7fbf2e`），危险 `#9c3b2e`
- 圆角：手机端仍 16 / 12 / 8；桌面端收紧为 9 / 7 / 5，避免卡片化
- 字体 PingFang SC 栈，等宽字体栈，缓动 `cubic-bezier(.22,.61,.36,1)`

## 检查结果

- 9 个视口 × 3 个端（控制台 / App / 网页版）无横向溢出、无控制台报错（27 组全通过）
- 端到端 HTTP 测试 43 项全通过，含预览解析、文件夹增删移、标签、搜索、Skill 方案与执行、存储迁移、安全边界
- 图标全部为内联 SVG（统一 1.6–1.9 描边），无 emoji 功能图标
- 主视觉无紫粉渐变，无毛玻璃 + 发光边框套路
- 桌面 App 实测：窗口 1440×900 内容区完整渲染；关窗后服务存活；强杀后后端自动退出；单实例只留一个进程；`/api/open-external` 白名单拦截 `file://` 与公网地址
- 安装包内容核对：`landrop.exe` + `landrop-server.exe` + `public/` + `skill/` 齐全
